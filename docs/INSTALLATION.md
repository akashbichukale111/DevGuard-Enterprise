# Installation

Four paths, smallest first. Pick the one that matches what you need to do.

| Path | What you get | Requirements |
|---|---|---|
| [1. Replay](#1-replay-only) | The Command Center over recorded runs | Python, Node |
| [2. Application](#2-application) | Scanner UI, API, telemetry | + a model provider key |
| [3. Full platform](#3-full-platform) | The live nine-agent loop | + DataHub, PostgreSQL, dbt |
| [4. With SigNoz](#4-with-signoz) | Traces, dashboard, alerts | + a SigNoz deployment |

**Prerequisites for every path:** Python 3.11+, Node 20.9+ (Next.js 16 declares
`engines: { node: ">=20.9.0" }` and refuses to build below it), and Git.

Run `make doctor` at any point. It reports what is present, what is missing, and
what each missing piece costs you.

---

## 1. Replay only

No API key, no catalog, no database, no network.

```bash
git clone https://github.com/akashbichukale111/DevGuard-Enterprise.git
cd DevGuard-Enterprise/frontend

npm ci && npm run dev
```

Open <http://localhost:3000/command>.

**Node only.** The replay bundles under `frontend/public/replay/` are committed, so
nothing has to be generated first. For the static export the hosted demo serves:

```bash
cd frontend && NEXT_OUTPUT=export npm run build   # → frontend/out/
```

`make replay-serve` does the same thing plus regenerating the bundles from the proof
packs, and does need Python.

Verify it does what it claims:

```bash
make test                # 1104 tests
make verify-replay-ui    # drives the built site in a real browser
```

## 2. Application

Adds the live scanner. A model provider key is needed for `POST /scan` only —
everything else works without one.

```bash
cp .env.example .env
# add GROQ_API_KEY=<your key> from https://console.groq.com/keys
```

Two terminals:

```bash
make backend     # python -m uvicorn backend.main:app --port 8000
make frontend    # cd frontend && npm run dev
```

Open <http://localhost:3000>.

Confirm the API is healthy:

```bash
curl localhost:8000/slo-status
curl localhost:8000/telemetry-status
```

Interactive API docs are at <http://localhost:8000/docs>.

### With containers

```bash
docker compose up
```

Container builds need network access to the Debian and PyPI mirrors. In
restricted environments the build fails on `apt-get` or on wheel downloads —
that is an environment constraint, not a defect. Run the services directly if you
hit it.

## 3. Full platform

The nine-agent loop needs a catalog with real lineage and a substrate that can
really break.

### 3a. DataHub

```bash
pip install "acryl-datahub==1.6.0.16"
datahub docker quickstart
```

> **Enable metadata service authentication before going further.** The
> quickstart ships with `METADATA_SERVICE_AUTH_ENABLED=false`, under which
> Access Policies are **not enforced at all** — every deny rule silently passes.
> Set it to `true` on the GMS container, preserving the token signing key, and
> recreate the container.

Create the least-privilege service account and verify it:

```bash
python scripts/setup_service_account.py
python scripts/verify_least_privilege.py
```

Expected:

```
ALLOW: 4/4 behaved as required
DENY : 5/5 correctly refused
```

If DENY reports 0/5, authentication is still disabled. Go back and fix it — see
[SECURITY.md](../SECURITY.md#least-privilege).

Store the token outside the repository, `chmod 600`, and export
`DATAHUB_TOKEN_FILE=/path/to/token`.

### 3b. The substrate

```bash
docker compose -f substrate/docker-compose.yml up -d
psql "$SUBSTRATE_PG_URL" -f substrate/seed/01_raw.sql

cd substrate/dbt && dbt build && cd ../..
python substrate/ml/train_churn_model.py
```

### 3c. Ingest into DataHub

```bash
datahub ingest -c recipes/postgres.yml
datahub ingest -c recipes/dbt.yml                    # produces column-level lineage
datahub ingest -c recipes/structured_properties.yaml
```

The dbt recipe is the important one — column-level lineage is generated by
ingestion, not authored by hand, which is what makes the blast radius a property
of the catalog rather than of a fixture.

### 3d. Run the loop

```bash
python scripts/reset_demo.py                          # put the substrate in the broken state
python scripts/run_d6_loop.py --run-id my-first-run
```

Other entry points:

```bash
python scripts/run_d4_evidence_chain.py --run-id chain     # read side only
python scripts/run_d5_diagnosis.py --scenario refusal      # the refusal path
make eval                                                  # fault-injection suite
make ablation                                              # retrieval ablation
```

## 4. With SigNoz

Either point at SigNoz Cloud:

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
OTEL_EXPORTER_OTLP_HEADERS=signoz-access-token=<key>
```

or self-host from the compose files in this repository — see
[DEPLOYMENT.md](../DEPLOYMENT.md#observability-signoz), which includes the
first-run registration step that is easy to skip and silently drops every span
when you do.

Install the dashboard and alert rules:

```bash
./scripts/apply_signoz_assets.sh
```

Verify telemetry without needing SigNoz at all:

```bash
python scripts/verify_otel.py
```

That stands up an in-process OTLP/gRPC receiver, boots the real application,
drives traffic through it, and asserts against decoded protobuf.

## Troubleshooting

**`make doctor` says the RAG backend is a lexical fallback.** Expected.
`chromadb` and `sentence-transformers` pull a ~5.4 GiB tree and are optional
accelerators behind `try/except`. Retrieval stays deterministic and relevant, but
is not semantic.

**Telemetry reports `exporter_configured: true` but nothing arrives.** If your
shell has an HTTPS proxy set, also set `no_grpc_proxy=localhost,127.0.0.1`. gRPC
reads its own proxy variables and `NO_PROXY` alone does not cover it.

**`POST /scan` fails but the server is up.** `GROQ_API_KEY` is unset. That is the
designed keyless behaviour — everything except scanning still works.

**DataHub document search returns nothing on a fresh catalog.** Also expected.
The server hides `search_documents` and `grep_documents` when no documents exist.
The Archivist negotiates capabilities and reports "no prior runbook" rather than
an error.

**`npm run build` fails on Node 18.** Next.js 16 requires Node ≥ 20.9.0.
