# Evidence

Captured artifacts from real runs against a real stack. Everything here was
produced by executing the code in this repository — nothing is written by hand,
and nothing is illustrative.

This directory exists so that the claims in the [README](../README.md) can be
checked without standing up any infrastructure.

## Layout

| Directory | Contents |
|---|---|
| [`proof-pack/`](proof-pack/) | One directory per recorded run. Every tool call, evidence item, agent handoff and write-back payload. The replay UI is built from these. |
| [`d0/`](d0/) | Catalog capability baseline: DataHub server config, the MCP tool list and full tool schemas as reported by the live server. |
| [`d1/`](d1/) | Every write path, proven individually against a live catalog. |
| [`d2/`](d2/) | The substrate ingested, with column-level lineage auto-generated by dbt ingestion. |
| [`d3/`](d3/) | The ML model registered and made traversable; blast radius before and after the break. |
| [`d4/`](d4/) | The evidence chain forming from real captured evidence. |
| [`d5/`](d5/) | Diagnosis, and a refusal demonstrated on a genuinely one-sided chain. |
| [`d6/`](d6/) | The full remediation loop, run twice from clean state. |
| [`d7/`](d7/) | The retrieval ablation. |
| [`d8/`](d8/) | The fault-injection evaluation suite. |
| [`d9/`](d9/) | Security posture: the injection demonstration and least-privilege verification. |
| [`d10/`](d10/) | The Command Center and zero-infrastructure replay, verified in a real browser. |

Directory names are stable identifiers. They are referenced by code, by tests and
by the replay manifest, so they are kept exactly as the runs recorded them —
renaming them would invalidate the artifacts they label.

## Proof packs

```
proof-pack/<run-id>/<agent>/
├── handoff.json          the AgentHandoff record for that agent
├── evidence/*.json       each evidence item, with source, trust and confidence
└── raw/*.json            the exact captured request and response
```

Seven packs build into replay bundles:

| Run | What it demonstrates |
|---|---|
| `d6-loop-pass2` | The complete loop, ending in five write-back artifacts that landed in DataHub |
| `d6-loop-pass1` | The same loop's first clean-state pass |
| `d6-dry-run` | Every write payload recorded, nothing sent |
| `d6-fail-the-fix` | A proposed fix failing validation — no human is asked, nothing is written |
| `d5-refusal` | The Diagnostician declining to guess, naming the missing evidence class |
| `d5-full` | A complete diagnosis over a two-sided chain |
| `d4-evidence-chain` | The evidence chain forming |

Plus `ablation/` (10 measurement runs), `eval/` (per-fault `dbt build` output
including the green baseline), and `security/` (injection demonstration and
least-privilege ALLOW/DENY checks).

## Reading a pack

```bash
make replay          # compile packs into replay bundles
make replay-serve    # browse them in the Command Center
```

Or read them directly — they are plain JSON, and the raw payloads are the bytes
the server actually returned.

## Redaction

Proof packs are redacted at capture time and size-capped with explicit
truncation markers. Credentials never enter a pack;
`tests/test_proof_pack_redaction.py` pins that boundary.
